Prompting in Public

In July 2026 I started prompting my coding agents publicly when working on open source projects, first on GitHub (example), and now on /dev/null (example).

My favorite thing about it is: when I prompt in public, every prompt has a public permalink. Benefits:

  • When a friend asks me how I did something, I can just link them to the actual prompt.
  • When an agent writes issues or certain kinds of docs (e.g. ADRs and agent briefs), it can permalink to the source prompt. This way, an agent’s summaries can be traced back and verified against the source.

Also, as more code gets written by AI, I find myself becoming more interested in how humans prompt their agents than in the AI-generated results1. I’d rather see people talking to agents than talking about agents.

How I set up my agents for prompting in public

I had my agents build bridges for communicating over a public channel. Basically, it’s a gangprompting setup adapted to public channels. So far I've built two bridges:

  • dtinth/claw (GitHub)
  • dtinth/dev-null-bridge (/dev/null)

With the bridges built, to start working on a new project in the open, I would:

  1. Create a GitHub issue or a /dev/null commit.
  2. Tell my agents to talk to me via the bridge instead of directly.

I do that by invoking the skill that gets shipped with the bridge:

Me:

/dtinth-claw let's talk in https://github.com/bemusic/bemuse/issues/844

…or:

Me:

/dev-null-bridge let's talk in https://dev-null.sh/@dtinth/commits/01a15555-27f2-7026-9b16-35c58c1cdb8d

If you’re curious about how to build these bridges, I’ve explained them in much more detail on the dedicated Gangprompting page. Please check it out.

Unlike in gangprompting, where the agent talks to everyone in the group chat, here my agent talks to me only. Therefore, the bridge should filter out messages that aren’t from me. If I want the agent to look at or respond to someone else’s messages, I have to tell my agent explicitly and link to that message.

Building a custom UI for GitHub communication

Inasmuch as I'd like to prompt my agents through GitHub, its issues UI is too janky for quick prompting, so I built a custom web dashboard where I can read and reply to my agents’ GitHub comments. The full conversation is on GitHub.

Building the /dev/null bridge on /dev/null

I built the /dev/null bridge mostly by prompting my agent on /dev/null. You can read the whole conversation here. I bootstrapped the project by:

  1. Cloning the dev-null.sh repo (it’s open source) and put my agent in it
  2. I asked it to commit (post) something on my bot account, then watch for my replies to it. This is easy because the agent has access to the platform’s source code, so it knows what to do. It built a rudimentary bridge.
  3. I started prompting it to turn that prototype into a central poller. We designed how subscriptions would work, built a web dashboard for inspecting, and discussed how to explain how it works with diagrams.

# Custom Widget Access Tokens in Grist

When integrating with [Grist](Grist), normally you would [use an API key to authenticate with Grist API](https://support.getgrist.com/rest-api/#authentication). However, it is long-lived and has a very broad scope: your API key provides access to everything you have access to, and each user can have only 1 API key, so rotating your API key breaks every integration that uses it.

- For self-hosters, you can create [**Service Accounts**](GristServiceAccounts) to represent a workload, but the tokens are still long-lived. Good for plugging into [n8n](N8n).
- For users of hosted Grist and the full edition of Grist, there’s also [**OAuth Apps**](https://support.getgrist.com/oauth-apps/), where app developers can [request fine-grained scopes](https://support.getgrist.com/oauth-apps/#scopes) and users can [grant access to only some documents](https://support.getgrist.com/oauth-apps/#resource-selections), but this is not part of [Grist Community Edition](https://support.getgrist.com/self-managed/#grist-community-edition).

There is yet another authentication mechanism available in _all Grist editions_, useful for granting *temporary access* to a *single document*: [**“Custom Widget Access Tokens”**](https://support.getgrist.com/code/interfaces/grist_plugin_api.AccessTokenResult/)[^disam].

## Quick introduction + demo

A **Custom Widget Access Token** is a JWT [generated by a custom widget](https://support.getgrist.com/code/interfaces/grist_plugin_api.GristDocAPI/#getaccesstoken), lasts for 15 minutes, scoped to the document that embeds the widget, and represents the user who uses the widget. It can be obtained by calling [`grist.docApi.getAccessToken`][obtain] from the custom widget. The token can then be used to call [Grist API](https://support.getgrist.com/api/) endpoints by [passing it via the `?auth=` query parameter](https://support.getgrist.com/code/interfaces/grist_plugin_api.AccessTokenResult/#token) _(not Authorization header!)_.

I built a custom widget that lets you generate and inspect access tokens ([open demo in Grist](https://docs.getgrist.com/4hUHYXRyJUz5/Access-Token-Inspector-Demo), [source code](https://github.com/dtinth/grist-widget/tree/master/access-token)):

## Use cases

### Giving AI agents temporary access to any Grist document

With this custom widget, you can copy the LLM prompt to your AI agent, to give it temporary access on any Grist document on any server, without having to manually manage API keys:

:::figure[Asking Claude to thoroughly explore and summarize a Grist document]{.framed}

![](https://im.dt.in.th/ipfs/bafybeiamr3regrgrk4y7mwcbeaukmwe3dd76byubn7qpg7ztj2abydqpva/image.webp)

:::

The access token is valid for 15 minutes, after which you must generate a new token and give it to the agent. Great for one-off tasks. If your agent has a network firewall, you must give them access to these domains:

| Domain | Reason |
| --- | --- |
| `docs.getgrist.com` | To access the Grist API (or if self-hosted, replace with your instance domain) |
| `raw.githubusercontent.com` | To access the API documentation |

---

### Building a sync pipeline triggered from a Grist custom widget

If you're using Grist as a headless CMS or as document management system, you might want to build a user-triggered pipeline, such as:

- Generating PDFs and saving them to Google Drive
- Triggering GitHub Actions workflows

While you can use [Webhooks](https://support.getgrist.com/webhooks/) or [Workflow Automations](https://www.getgrist.com/automations/) to build this pipeline, you can also let user do it from a custom widget as well. Your custom widget would [obtain an access token][obtain], and pass it to the backend. The backend should:

1. Receive an access token from the custom widget
2. Identify the user using [GET /profile/user](https://support.getgrist.com/api/#tag/profile/operation/getProfile)
3. Check if user has access to the doc, e.g. by using [GET /docs/{docId}/tables](https://support.getgrist.com/api/#tag/tables/operation/listTables)
4. Perform the data synchronization

---

### Displaying attachments in a Grist custom widget

Normally a custom widget receives the attachment's numeric ID. To display it in a custom widget, you would need to:

1. [Obtain an access token][obtain]
2. Construct an attachment download URL: [GET /docs/{docId}/attachments/{attachmentId}/download](https://support.getgrist.com/api/#tag/attachments/operation/downloadAttachment) with `?auth=` query param appended
3. Use that URL to render an image element

For more information, see forum thread: [_Accessing attachments from Custom Widget builder_](https://community.getgrist.com/t/accessing-attachments-from-custom-widget-builder/7814)

---

### Other use cases

With an access token, your custom widget can do things beyond what its [Plugin API](https://support.getgrist.com/code/modules/grist_plugin_api/) normally provides, such as:

- [Uploading](https://support.getgrist.com/api/#tag/attachments/operation/uploadAttachments) [attachments](https://support.getgrist.com/api/#tag/attachments)
- [Querying a table with sorting and filtering](https://support.getgrist.com/api/#tag/records/operation/listRecords) ([`grist.docApi.fetchTable`](https://support.getgrist.com/code/interfaces/grist_plugin_api.GristDocAPI/#fetchtable) fetches the whole table without any filtering)
- [Running SQL queries on the Grist document](https://support.getgrist.com/api/#tag/sql)

[obtain]: https://support.getgrist.com/code/interfaces/grist_plugin_api.GristDocAPI/#getaccesstoken

## JWT claims inside an access token

:::caution
This is an implementation detail, only noted here for the curious. In practice, you should treat the token as an opaque string.
:::

```json
{
  "readOnly": true,
  "userId": 55576,
  "docId": "qNCfWjZErhkt74Rtn3CtXL",
  "iat": 1779978355,
  "exp": 1779979255
}
```

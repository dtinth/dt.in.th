# UDP hole punching in Jamulus

While developing [a Go implementation of Jamulus protocol client](https://github.com/dtinth/gojam), I ran into an issue where my client cannot connect to a the server, whereas the normal [Jamulus](Jamulus) client can.

Turns out this is due to many Jamulus servers are behind a firewall. They don’t accept UDP packets from strangers.

![](https://static.dt.in.th/uploads/2023/01/09/punch1.svg)

It turns out that the Directory Server faciliates the connection by using the [UDP hole punching](https://en.wikipedia.org/wiki/UDP_hole_punching) technique.

![](https://static.dt.in.th/uploads/2023/01/09/punch2.svg)

The hole punching logic is in [CServerListManager::RetrieveAll](https://github.com/jamulussoftware/jamulus/blob/b8c2095494f2465649678e3dc09ba85492c80732/src/serverlist.cpp#L717-L721), which gets called on [CServer::OnCLReqServerList](https://github.com/jamulussoftware/jamulus/blob/b8c2095494f2465649678e3dc09ba85492c80732/src/server.h#L358), which gets triggered on the [CProtocol::CLReqServerList](https://github.com/jamulussoftware/jamulus/blob/b8c2095494f2465649678e3dc09ba85492c80732/src/protocol.cpp#L2231) event, handled via the [`PROTMESSID_CLM_REQ_SERVER_LIST` (1007)](https://github.com/jamulussoftware/jamulus/blob/b8c2095494f2465649678e3dc09ba85492c80732/src/protocol.cpp#LL872-L873C49) protocol message.

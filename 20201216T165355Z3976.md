The project I want to build is a web-based local file storage.

**Why?** Nowadays, there are so many web-based tools that work with files, such as:

- [Squoosh](https://squoosh.app/ 'Squoosh') image compressor
- [Photopea](http://www.photopea.com/ 'Photopea | Online Photo Editor') photo editor
- [gifcap](https://gifcap.dev/ 'gifcap') screen recorder
- [Diagrams.net](https://www.diagrams.net/ 'Diagram Software and Flowchart Maker') diagram and flowchart maker
- [vox.spacet.me](https://vox.spacet.me/) voice recorder (I made this one)
- [json.spacet.me](https://json.spacet.me/) JSON viewer (I made this one too)
- [instant.io](http://www.instant.io/ 'Instant.io - Streaming file transfer over WebTorrent') streaming file transfer over WebTorrent
- [ShareDrop](https://www.sharedrop.io/ 'ShareDrop') file transfer over WebRTC
- [StackEdit](https://stackedit.io/ 'StackEdit – In-browser Markdown editor') and [Dillinger](https://dillinger.io/ 'Online Markdown Editor - Dillinger, the Last Markdown ...') Markdown editor
- [Carbon](https://carbon.now.sh/ 'Carbon | Create and share beautiful images of your source code') code image generator
- other specialized tools that I create for specific situations

**Now comes my pain point:** When I want to use multiple apps together, I have to go through a lot of Download-then-Upload experience, and thus my Downloads folder fills up with many temporary files.

**Many apps are inconsistent in how they handle input/output.** To get data into a web app, you can use the usual [File open][openfile] dialog (via `<input type="file">`), the [Drag and Drop API][dnd], the [Clipboard API][pasteimg], and the [Share Target API][sharetarget]. To get data out, there's `<a>`'s [download][dlattr] attribute, [DownloadURL DataTransfer type for dragging files out of the browser][downloadurl], the [Clipboard API][clipboard], the [Web Share API][webshare], and the classic "Save Link As", "Save Image As" and "Copy Image" menu items.

Most apps support only a subset of these APIs. Some apps also have integrations with cloud storage services like Google Drive, but many don't. [Paul Kinlan (2017). “Web sites as unintended silos: The problem with getting data in and out of the web client.”](https://paul.kinlan.me/unintended-silos/) is an interesting read.

Now the web has the [`postMessage`][message] API that lets web applications throw data around among different websites. So, I'm pondering about the idea of having a web-based portal, a hub of sort, that takes care of importing/exporting files using all the available Web APIs...

![](https://static.dt.in.th/uploads/2020/12/18/tmp-core.png)

...and integrates with all the different apps.

![](https://static.dt.in.th/uploads/2020/12/18/tmp-extension.png)

**It should be extensible.** Of course I'm lazy and I won't be integrating all the different apps myself. Instead, integrations will be provided through an extensions system. (In the above picture, the text in blue are to be implemented as an extension rather than as a core feature.)

If all goes according to the plan, extensions will be HTML pages and communicate with this app through the `postMessage` API. This way new extensions can be written using any tool, and added to the app without having to touch the main app. This is a nice opportunity to learn about "[micro-frontends][micro]."

**Deployment structure:** The main app will be deployed as a Static Site application, while extensions may be deployed as separate apps, and some of them might require a database. This is also an opportunity to try out App Platform services such as [DigitalOcean Managed Databases][db].

**Project name:** This is one of the hardest thing in computer science. I intended it to be a place where I temporarily put files in. For the lack of better name, I just called it "tmp".

**Project setup:** I applied for a DigitalOcean credit, created a [Next.js][nextjs] static app, set up [Tailwind][tailwindnext], [TypeScript][nextts] and [next-pwa][next-pwa]. I deployed the app to DigitalOcean App Platform and it just works (except the part where I waited for the spinner to finish. By the way everyone, please don't add a spinner if you will not also automatically refresh it.)

**Implementating the core features:** I then implemented the basic import/export functionalities using various Browser APIs and npm packages:

- [Clipboard API][clipboard]
- [Web Share Target API][sharetarget]
- [DownloadURL for Drag and Drop][downloadurl]
- [window.open()][windowopen]
- [downloadjs][downloadjs]
- [Browser-NativeFS][browser-nativefs]

File data and all other data will be stored inside IndexedDB, through the help of [PouchDB][pouch]. Querying data from the local database in the React app is done using [React Query][query].

[downloadjs]: https://www.npmjs.com/package/downloadjs
[windowopen]: https://developer.mozilla.org/en-US/docs/Web/API/Window/open
[browser-nativefs]: https://www.npmjs.com/package/browser-nativefs
[pouch]: https://pouchdb.com/
[query]: https://react-query.tanstack.com/

After a few days of coding, most of the core features are implemented.
Now, for example, I can share photos from Google Photos directly to tmp.
Within tmp, I can view the image (using the browser's built-in image viewer) and share it to other apps.

![](https://static.dt.in.th/uploads/2020/12/18/tmp-sharing.png)
